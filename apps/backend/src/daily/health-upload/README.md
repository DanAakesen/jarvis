# Inactive Health Auto Export buffer

[P12-04 release](https://github.com/DanAakesen/jarvis/issues/719#issuecomment-6135270257) and [verified source contract](https://github.com/DanAakesen/jarvis/issues/719#issuecomment-6131298107) authorize code-only upload/heartbeat acceptance. Production `index.ts`, modules and deployment templates never instantiate this dedicated factory. No provisioning, device credentials, human-auth changes, processing or activation are included.

Explicitly enabled JSON POST `/api/health/ingest` requires `automation-id` and `session-id`. Optional upload `checksum`/`x-payload-checksum` must match SHA-256 of original bytes. UTF-8 upload JSON is bounded to 8 MiB and retained byte-exact without normalizing metrics, units, timezone or empty workouts. Source-compatible `/api/health/heartbeat` accepts bodyless POST without Content-Type; its ignored optional body is bounded to 32 KiB. It durably records private `shortcutName` from the unique bounded (256-character) `shortcut-name` header, default `Daily Overview heartbeat`, and `checkedFeeds: [metrics, workouts]`. Optional identity headers otherwise use a fresh server session. This header provenance stays out of pointers/responses/logs. Heartbeat acceptance never means health ingestion was processed.

Each request reads a private `health-devices/<SHA-256 of opaque bearer>.json` capability. External provisioning/revocation remains gated. Records bind the configured existing Jarvis owner Object ID, device ID, `health-ingest`/`health-heartbeat`, expiry and revocation; missing/wrong/expired/revoked records deny access and storage failures fail closed. Client owner/email selectors have no authority. These capabilities cannot authenticate ordinary Jarvis or nutrition-export routes. Human passwords and legacy/broad tokens are not copied.

Private immutable raw objects and conditional owner/kind/automation/session manifests precede HTTP 202. Same checksum retries reuse the original acceptance ID/time; changed payload conflicts. Non-expiring Queue messages contain only opaque manifest pointers. Conditional delivery updates prevent concurrent overwrites. Queue failure reports accepted/pending because the Blob outbox remains durable; SQL and agents are not dependencies. Cancellation before receipt makes no acknowledgement promise. Ambiguous queue/response gaps permit duplicate pointers, not exactly-once external effects.

Trusted `recover()` scans one bounded page with explicit continuation/errors and replays pending pointers; `replayQueued` is explicit operator recovery. It is not a registered endpoint or schedule. No raw/manifest deletion or lifecycle policy is installed. Unacknowledged raw-only crash remnants may exist. #720 owns processing, owner/checksum validation, deduplication, poison handling and processed freshness after durable SQL commit.

The future factory accepts injected Azure `TokenCredential` and configured same-account HTTPS endpoints. Managed identity is intended, not granted. Existing private containers/queue are required. Microsoft [Blob](https://github.com/Azure/azure-sdk-for-js/tree/main/sdk/storage/storage-blob) and [Queue](https://github.com/Azure/azure-sdk-for-js/tree/main/sdk/storage/storage-queue) installed README/API declarations informed SDK 12.31.0/12.32.0 usage. Queue TTL `-1` avoids seven-day expiration. SDK retries/deadlines, request concurrency and metadata reads are bounded; public containers are refused and responses/logging exclude raw data and tokens.

After explicit cloud activation, run `npm test --workspace @jarvis/backend -- src/daily/health-upload/buffer.emulator.test.ts`. Normal backend tests include actual HTTP/SDK/Azurite 3.37.0 persistence, concurrency/conflict, revocation/owner/scope, Queue outage/recovery, ambiguous sends, real gateway SIGKILL, cancellation, exact 8-MiB bounds and heartbeat. Compiled child imports exercise runtime artifacts. Synthetic random emulator accounts and temporary storage are removed; no loose/API-version bypass flags or production fixtures are used. This is emulator proof, not Azure verification.
